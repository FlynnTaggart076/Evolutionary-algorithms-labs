# Лабораторная работа № 3

Вариант 1. Трек A: портфель проектов, три критерия. Ключевые операторы NSGA-II реализованы в `portfolio.py`; готовые оптимизаторы не используются.

Из корня проекта (PowerShell):

```powershell
.\.venv\Scripts\python.exe Lab3\main.py
.\.venv\Scripts\python.exe -m pytest Lab3 -q
```

Установка общего окружения описана в корневом README. Рабочая директория может быть любой: входные пути по умолчанию вычисляются относительно скрипта.

Полная серия: 20 seed × два метода × 12000 оценок. Повтор и изменение бюджета:

```powershell
.\.venv\Scripts\python.exe Lab3\main.py --config Lab3\config.json --runs 20 --seed-start 300 --budget 12000
```

`data/projects.csv` - фиксированные входные данные. Если файл отсутствует, он воспроизводимо генерируется с seed из конфигурации. Ручное изменение входных данных меняет экземпляр задачи. `config.json` содержит параметры и зависимости с индексами от 0; в отчёте проекты пронумерованы от 1.

Колонка `project` содержит уникальные ID от 1 до n. Строки можно переставлять: программа сначала упорядочивает их по ID, сохраняя смысл зависимостей и названий решений. Коэффициенты должны быть конечными неотрицательными числами. Другую таблицу можно передать через `--data path\projects.csv`; её размер должен совпадать с `projects` в конфигурации. Основной код предназначен для варианта 1, трека A.

`results/runs.csv` хранит результаты каждого запуска, `summary.json` - описательную статистику, `config_used.json` - фактическую конфигурацию. Архивы каждого запуска записаны в `front_*.csv`; точный эталон - в `exact_front.csv`. `history.csv` хранит размер архива по оценкам (взвешенные поиски записаны отдельно). `representatives.json` содержит три решения первого запуска. Графики: проекции фронта, разброс IGD и покрытия, схема алгоритма. Итог: `report.md` и `report.pdf`.

`data_manifest.json` фиксирует путь и SHA-256 фактической входной таблицы, а также её совпадение с генератором при указанном seed. Отчёт отражает реальные ограничения, зависимости и список весов. Инициализация использует независимые биты с вероятностью единицы 0.35 и последующий ремонт; размер турнира равен двум. Эти два параметра зафиксированы в коде и явно описаны в отчёте.

Бюджет считается по обращениям к вектору критериев; все три компоненты вычисляются совместно. Оценки полного перебора используются только как эталон. Время включает сортировку и ведение архива, поэтому равенство числа оценок не означает равенства времени.

Команда перезаписывает результаты и Markdown-отчёт. После изменения числа запусков следует восстановить полную серию перед сдачей и пересобрать PDF: `python tools/build_reports.py`.

При `--output` с отдельным каталогом основной отчёт не перезаписывается: такой запуск предназначен для дополнительных экспериментов.

Число запусков и размер популяции должны быть положительными целыми числами, популяция - не меньше двух. Вероятности лежат в [0,1]. Для каждого взвешенного ГА требуется тройка конечных неотрицательных весов с положительной суммой и бюджет не меньше размера популяции; общий бюджет делится между весами с разницей не более одной оценки. Некорректные параметры отклоняются до начала эксперимента.
